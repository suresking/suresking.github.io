    EncodingHelper 增强版文件编码检测工具类（.NET 6+）。

    提供三套 API，按文件规模与使用场景选择：

    • 全量读取：ReadFileWithEncoding(String) / ReadFileWithEncodingAsync(String, CancellationToken)， 一次性读入内存并解码，适合中小文件。
    • 仅探测头部：GetFileEncoding(String) / DetectFileEncoding(String) 及其异步、Probe 变体， 只读取文件头部若干字节用于判断编码，适合超大文件或只需知道编码的场景。
    • 流式读取：OpenReader(String, Int32, Int32) / ReadLinesAsync(String, FuncString, CancellationToken, ValueTask, Int32, CancellationToken)， 以恒定内存占用逐行处理超大文件。

    检测优先级：BOM → 严格 UTF-8 校验 → 第三方统计检测（置信度阈值）→ 兜底。 兜底策略因 API 而异：全量读取兜底为 Gb18030，头部探测兜底为 UTF8。

    Enumeration 一个强类型枚举（Smart Enum）基类。

    ⚠️ 重要：枚举项必须使用"单例写法"，否则会埋下隐患。

    推荐（整个进程内唯一实例）：

    public static readonly CardType Amex = new(1, nameof(Amex)); // 字段 public static CardType Visa { get; } = new(2, nameof(Visa)); // 只读属性

    不推荐（每次访问都 new 一个新实例）：

    public static CardType MasterCard => new(3, nameof(MasterCard)); // ❌ 每次访问都 new

    原因：Enumeration 内部会缓存每个枚举项，FromIdT(Int32) / FromNameT(String) 返回的是缓存中的那个实例，而属性写法每次 返回新实例。虽然 Equals / == 仍会判定相等，但以下场景会出问题：

    • 用枚举项做 Dictionary / HashSet 的 key 时，引用不一致
    • 用 ReferenceEquals 判断时结果不符预期
    • 附加了可变字段（未来扩展）时，实例状态无法共享

    完整用法示例：

    public class CardType : Enumeration { public static readonly CardType Amex = new(1, nameof(Amex)); public static readonly CardType Visa = new(2, nameof(Visa)); public static readonly CardType MasterCard = new(3, nameof(MasterCard)); public CardType(int id, string name) : base(id, name) { } }

    SuresKingViewAttribute 标记一个类是「可被 IoC 容器批量注册的 View」。

    启动时扫描程序集，凡是带有此特性的类都会被批量注册到 DryIoc 容器中。 由于 View 通常需要按具体类型解析（而不是按某个公共接口）， 注册时使用具体类型本身作为服务类型，而不是映射到某个接口。

    使用方式： [SuresKingView] public partial class GithubView : UserControl { }

    为什么用特性而不是空标记接口（如 IView）： 特性不占用类型名，不会与其他类库中常见的 IView 等名称产生 using 歧义； 同时语义上更贴合「标记」，不强制被标记类继承或实现任何东西。

    SuresKingViewModelAttribute 标记一个类是「可被 IoC 容器批量注册的 ViewModel」。

    启动时扫描程序集，凡是带有此特性的类都会被批量注册到 DryIoc 容器中。 ViewModel 一般通过构造函数注入到对应的 View 中， 因此注册时同样以具体类型作为服务类型即可； 除非存在「按接口/基类注入」的需求，否则不需要额外的接口映射。

    使用方式： [SuresKingViewModel] public class GithubViewModel : ObservableObject { }

    与 SuresKingViewAttribute 分开定义， 是为了让 View 和 ViewModel 可以独立扫描、独立注册， 避免把两类职责不同的类型混在同一个筛选条件里。

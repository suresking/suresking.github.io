    EncodingHelper 类

    增强版文件编码检测工具类（.NET 6+）。

    提供三套 API，按文件规模与使用场景选择：

    • 全量读取：ReadFileWithEncoding(String) / ReadFileWithEncodingAsync(String, CancellationToken)， 一次性读入内存并解码，适合中小文件。
    • 仅探测头部：GetFileEncoding(String) / DetectFileEncoding(String) 及其异步、Probe 变体， 只读取文件头部若干字节用于判断编码，适合超大文件或只需知道编码的场景。
    • 流式读取：OpenReader(String, Int32, Int32) / ReadLinesAsync(String, FuncString, CancellationToken, ValueTask, Int32, CancellationToken)， 以恒定内存占用逐行处理超大文件。

    检测优先级：BOM → 严格 UTF-8 校验 → 第三方统计检测（置信度阈值）→ 兜底。 兜底策略因 API 而异：全量读取兜底为 Gb18030，头部探测兜底为 UTF8。

    方法

    DetectFileEncoding 尝试检测文件编码（只读取文件头部）。 返回 null 表示"信息不足，无法可靠判断"，由调用方决定兜底策略。
    DetectFileEncodingAsync 异步尝试检测文件编码（只读取文件头部）。返回 null 表示信息不足。
    DetectFileEncodingByProbe 尝试检测文件编码（只读取头部前 probeSize 字节）。 返回 null 表示"头部信息不足（例如全 ASCII），无法可靠判断"。
    DetectFileEncodingByProbeAsync 异步尝试检测文件编码（只读取头部）。返回 null 表示信息不足。
    GetFileEncoding 精准检测文件编码（只读取文件头部，不做全量加载）。 若信息不足（例如头部全是 ASCII），返回 UTF-8 兜底。
    GetFileEncodingAsync 异步精准检测文件编码（只读取文件头部）。 信息不足时返回 UTF-8 兜底。
    GetFileEncodingByProbe 检测文件编码（只读取头部前 probeSize 字节，适合超大文件）。 若信息不足，返回 UTF-8 兜底。
    GetFileEncodingByProbeAsync 异步检测文件编码（只读取头部，适合超大文件）。 信息不足时返回 UTF-8 兜底。
    OpenReader 打开带编码自动检测的 StreamReader（流式读取，内存占用恒定，适合超大文件）。

    先用探测 API 判断初始编码，再由 StreamReader 在读取过程中根据 BOM 自动校正。

    OpenReaderAsync 异步打开带编码自动检测的 StreamReader（流式读取，适合超大文件）。
    ReadFileWithEncoding 读取文件内容并检测编码（一次性读取，适合中小文件）。

    检测策略见 DecodeBytes(Byte)：BOM 优先；无 BOM 时依次尝试严格 UTF-8、统计检测， 全部无法可靠判定时兜底为 Gb18030。

    ReadFileWithEncodingAsync 异步读取文件内容并检测编码（一次性读取，适合中小文件）。
    ReadLinesAsync 逐行流式读取超大文件（自动检测编码）。每行回调 onLine。

    读取过程中在每次迭代前检查取消令牌，因此可以及时响应取消。 注意：回调函数按顺序串行执行，切勿在回调中执行长时间阻塞操作，否则会拖慢整体读取。

    ReadTextWithDetectedEncoding 读取文件并返回内容 + 原始编码（用于"读取后再以原编码写回"场景）。

    内部调用 ReadFileWithEncoding(String)，会一次性读取整个文件。

    ReadTextWithDetectedEncodingAsync 异步读取文件并返回内容 + 原始编码（用于"读取后再以原编码写回"场景）。

    字段

    Gb18030 中文场景常用兜底编码（GBK/GB2312 的超集）。
    Utf8NoBom 无 BOM 的 UTF-8（写回时使用，避免在文件开头引入 BOM）。
